# راهنمای اقدامات هاست برای افزایش سرعت MED School

این اقدامات مخصوص شرایط سایت فعلی شماست: cPanel / CloudLinux NodeJS Selector / دامنه medschool.ir / هاست کوچک.

## چرا با وجود حجم کم سایت ممکن است کند باشد؟

کندی همیشه از حجم فایل نیست. در هاست‌های اشتراکی معمولاً این موارد مهم‌ترند:

1. **Cold Start در NodeJS Selector / Passenger**
   اگر سایت چند دقیقه درخواست نگیرد، فرایند Node ممکن است idle شود. اولین کاربر بعد از idle باید منتظر روشن‌شدن دوباره برنامه بماند.

2. **TTFB بالا**
   یعنی زمان دریافت اولین بایت از سرور زیاد است. حتی اگر سایت ۲ مگابایت باشد، اگر TTFB مثلاً ۲ تا ۵ ثانیه باشد، سایت کند حس می‌شود.

3. **فاصله سرور تا کاربران ایران**
   اگر سرور در اروپا/آمریکا باشد، latency برای کاربر ایرانی بیشتر است.

4. **نبود CDN یا تنظیم نبودن cache در لبه شبکه**
   فایل‌های static مثل JS/CSS/font باید از نزدیک‌ترین edge به کاربر سرو شوند.

5. **محدودیت CPU/RAM هاست اشتراکی**
   CloudLinux ممکن است CPU/PMEM/Entry Process را محدود کند.

# مرحله ۱: تنظیم صحیح NodeJS Selector در cPanel

در cPanel → Setup Node.js App:

```text
Application root: medschool
Application startup file: app.cjs
Application mode: Production
Node.js version: 20 یا بالاتر
```

در Environment Variables:

```text
NODE_ENV=production
DATA_DIR=../medschool-data
```

اگر APP_URL دارید:

```text
APP_URL=https://medschool.ir
```

بعد:

1. Stop App
2. Run NPM Install
3. Restart App

نکته مهم:
داخل پوشه application root نباید `node_modules` واقعی آپلود شود. CloudLinux خودش symlink می‌سازد.

# مرحله ۲: Cron برای جلوگیری از Cold Start

در cPanel → Cron Jobs یک Cron Job بسازید.

اگر اجازه هر ۵ دقیقه دارید:

```bash
*/5 * * * * curl -fsS https://medschool.ir/api/health >/dev/null 2>&1
```

اگر curl در هاست نبود:

```bash
*/5 * * * * wget -q -O - https://medschool.ir/api/health >/dev/null 2>&1
```

اگر هاست اجازه هر ۵ دقیقه نمی‌دهد، هر ۱۵ دقیقه بگذارید:

```bash
*/15 * * * * curl -fsS https://medschool.ir/api/health >/dev/null 2>&1
```

این کار باعث می‌شود برنامه Node کمتر idle شود و اولین بازدیدکننده معطل cold start نشود.

# مرحله ۳: فعال‌سازی Cloudflare

اگر دامنه روی Cloudflare نیست، بهترین کار برای سرعت واقعی کاربران ایران، استفاده از Cloudflare است.

## تنظیمات DNS

رکورد دامنه اصلی:

```text
Type: A یا CNAME
Name: @
Proxy: Proxied / نارنجی
```

برای www هم اگر دارید:

```text
Type: CNAME
Name: www
Target: medschool.ir
Proxy: Proxied / نارنجی
```

# مرحله ۴: تنظیمات Cloudflare برای سرعت

در Cloudflare → Speed → Optimization:

## فعال کنید

```text
Brotli: ON
HTTP/3: ON
0-RTT: ON اگر موجود بود
Early Hints: ON
```

## با احتیاط

```text
Auto Minify JS/CSS/HTML: OFF یا فقط HTML/CSS
```

چون فایل‌های Vite از قبل minify شده‌اند. Minify دوباره گاهی مشکل ایجاد می‌کند.

## خاموش بماند

```text
Rocket Loader: OFF
```

Rocket Loader ممکن است React/Vite را خراب کند یا باعث خطاهای عجیب شود.

# مرحله ۵: Cache Rules در Cloudflare

## Rule 1 — Cache assets

مسیر:

```text
URI Path starts with /assets/
```

تنظیمات:

```text
Cache eligibility: Cache
Edge TTL: 1 month یا 1 year
Browser TTL: 1 year
```

## Rule 2 — Bypass API

مسیر:

```text
URI Path starts with /api/
```

تنظیمات:

```text
Cache eligibility: Bypass cache
```

## Rule 3 — HTML no aggressive cache

مسیر:

```text
URI Path equals /
یا URI Path does not start with /assets/
```

تنظیمات:

```text
Cache eligibility: Standard یا Bypass برای HTML
```

توصیه: HTML را cache سنگین نکنید، چون محتوای SEO و مسیرها ممکن است پویا باشد.

# مرحله ۶: Bot Fight / Rate Limit برای کاهش فشار روی هاست

در Cloudflare اگر رایگان دارید:

```text
Bot Fight Mode: ON
```

اگر WAF Rules دارید، این user-agentها را محدود کنید، نه لزوماً بلاک کامل:

```text
GPTBot
ClaudeBot
PerplexityBot
CCBot
AhrefsBot
SemrushBot
MJ12bot
```

چرا؟
روی هاست کوچک، botها می‌توانند CPU را مصرف کنند و TTFB کاربران واقعی را بالا ببرند.

# مرحله ۸: تست بعد از تنظیمات

بعد از اعمال تنظیمات، این‌ها را تست کنید:

## تست سلامت

```text
https://medschool.ir/api/health
```

باید JSON بدهد و سریع باز شود.

## تست صفحه اصلی

```text
https://medschool.ir
```

## تست cache فایل assets

در مرورگر DevTools → Network روی یک فایل JS در `/assets/` کلیک کنید.
باید ببینید:

```text
cache-control: public, max-age=31536000, immutable
content-encoding: br یا gzip
cf-cache-status: HIT یا MISS
```

MISS بار اول طبیعی است؛ بار دوم باید HIT شود.

# مرحله ۹: اگر هنوز کند بود

اگر بعد از Cloudflare و Cron هنوز کندی داشتید، منشأ احتمالاً یکی از این‌هاست:

1. CPU/RAM هاست کم است.
2. Passenger خیلی زود app را idle می‌کند.
3. TTFB به‌خاطر موقعیت سرور زیاد است.
4. هاست برای Node.js مناسب نیست.

در این حالت بهترین ارتقای واقعی:

```text
VPS کوچک با 1-2GB RAM نزدیک ایران یا اروپا + Node + Nginx + PM2
```

حتی VPS سبک معمولاً از NodeJS Selector روی هاست اشتراکی سریع‌تر و پایدارتر است.

# جمع‌بندی سریع

اگر فقط سه کار انجام دهید، این‌ها بیشترین اثر را دارند:

1. Cloudflare با Brotli + HTTP/3 + cache assets
2. Cron keep-alive هر ۵ یا ۱۵ دقیقه
3. NodeJS Selector روی Production و بدون node_modules آپلودی

این سه مورد معمولاً TTFB و حس کندی سایت را خیلی بهتر می‌کنند.
