# راهنمای کار با ایجنت‌های هوش مصنوعی در پروژه MED School

## چرا این راهنما لازم است؟
ایجنت‌های هوش مصنوعی در کدنویسی سریع‌اند، اما معمولاً این موارد را از قلم می‌اندازند:

- نیاز واقعی کسب‌وکار و acceptance criteria
- محدودیت‌های هاست و deployment
- امنیت auth / role / CSRF / upload
- سرعت و bundle size
- تست‌های regression
- اثر تغییر روی ظاهر فعلی
- داده‌های پژوهشی و حریم دانشجو
- حالت disabled/off برای قابلیت‌های جدید
- مهاجرت دیتابیس و سازگاری با دیتای قبلی
- ZIP نهایی مناسب cPanel

## قواعد کار با AI agent

1. قبل از تغییر، مسئله را دقیق تعریف کن.
2. از agent بخواه اول plan بدهد، بعد کد بزند.
3. تغییر را کوچک نگه دار.
4. بعد از هر فاز تست بگیر.
5. هر تغییر UI باید با screenshot یا مرورگر تست شود.
6. هر تغییر API باید تست سرور داشته باشد.
7. هر ویژگی جدید باید خاموش/روشن داشته باشد اگر روی دانشجو/ادمین/پژوهش اثر دارد.
8. هر خروجی نهایی باید ZIP بدون node_modules باشد.

## چطور از agent بخواهید درست کار کند؟
نمونه prompt:

«با توجه به AGENTS.md و skill medschool-qa، این قابلیت را اضافه کن. ظاهر سایت را تغییر نده. اول plan بده. بعد تغییرات را اعمال کن. بعد build و تست سرور را اجرا کن. ZIP نهایی بدون node_modules بساز.»

## مواردی که agent نباید بدون اجازه انجام دهد

- افزودن dependency سنگین
- تغییر ظاهر کلی سایت
- حذف فایل‌های اصلی یا داده
- تغییر startup file cPanel
- تغییر ساختار ZIP
- حذف تست‌ها
- hardcode کردن API key
- روشن کردن قابلیت AI/ads به صورت پیش‌فرض

## نکات عملی اضافه‌شده بعد از بررسی ویدیوی Hozhi

ویدیوی بررسی‌شده: `https://www.youtube.com/watch?v=b1utIB_tLZw`

نکات کاربردی که برای MED School اعمال شد:

1. **بکاپ قبل از آپدیت live**: قبل از هر تغییر روی هاست، باید از فایل‌های برنامه و پوشه داده/دیتابیس بکاپ گرفته شود.
2. **آپگرید دیتابیس بدون آسیب به اطلاعات قبلی**: تغییرات دیتابیس باید افزایشی و قابل اجرای دوباره باشد؛ دستورهای تخریبی مثل `DROP` یا `DELETE` برای آپگرید عادی ممنوع است.
3. **عدم آپلود داده runtime**: فایل ZIP نهایی نباید `medschool-data`، `data`، یا فایل‌های دیتابیس مثل `.db/.sqlite` داشته باشد؛ چون ممکن است اطلاعات واقعی سایت را خراب یا جایگزین کند.
4. **عدم جایگزینی کورکورانه تنظیمات live**: اگر سایت قبلاً روی هاست فعال است، فایل `.env` واقعی باید با احتیاط حفظ شود.
5. **چک SEO و امنیت پیش از تحویل**: `robots.txt`، `sitemap.xml`، محافظت ادمین/API، CSRF، CSP و rate limit باید بررسی شوند.
6. **چک خودکار ZIP**: اسکریپت `scripts/check-release-zip.mjs` اضافه شد تا قبل از تحویل ZIP، ساختار مناسب cPanel و نبودن فایل‌های ممنوع را چک کند.

نمونه دستور چک ZIP:

```bash
node scripts/check-release-zip.mjs /home/user/MED-School-10-final.zip
```
