# کدام هاستِ ایران‌هاست برای MED School مناسب‌تر است؟ + آیا پلنِ 2/1/1 کافی است؟

## پاسخِ کوتاه به سؤالِ منابع
**پلنِ فریم‌ورک پلاس با Hard: 2GB · CPU: 1 · RAM: 1GB برای شروع و رشدِ اولیه «کافی» است — با یک احتیاط دربارهٔ «build».** ✅
همان «فریم‌ورک پلاس» را بگیر (نه نودجی‌اسِ ابریِ پایه). اگر بخواهی خیالت کاملاً راحت باشد، RAM: 2GB بگیر که فقط برای مرحلهٔ build راحت‌تری بدهد.

## اعدادِ واقعی (که خودم اندازه گرفتم، روی محیطی با همان ۲ هسته / ۲GB)

| چیز | مصرفِ واقعی | نتیجه برای پلنِ 1GB |
|---|---|---|
| **سرورِ Node در حالِ اجرا (idle)** | ~۲۹۰ مگابایت رم (با بانکِ ۱۱٬۶۰۰ سؤالی که کامل در حافظه است؛ اندازه‌گیریِ v71) | ✅ راحت |
| **سرور زیرِ بار** | تقریباً ثابت (بدونِ نشتِ حافظه؛ ذخیرهٔ دیتابیس فقط وقتی چیزی تغییر کرده باشد) | ✅ عالی |
| **دیتابیسِ اولیه روی دیسک** | ~۰.۹ مگابایت (فقط با رشدِ محتوا/کاربر بزرگ می‌شود) | ✅ |
| **کلِ کد + node_modules + dist روی دیسک** | ~۱۷۷ مگابایت | ✅ زیرِ ۲GB جا می‌شود |
| **build کلاینت (سنگین‌ترین لحظه)** | اوج ~۴۵۸ مگابایت رم | ⚠️ روی ۱GB معمولاً می‌شود، ولی حاشیهٔ امن کم است |

> **مهم‌ترین یافته:** سرورِ در حالِ اجرا حدود ۳۰۰MB رم می‌خواهد (نسخه‌های ۶۸ تا ۷۰ تا ~۴۵۰MB می‌رفتند که روی هاستِ ۱GB خطرناک بود؛ در v71 کم شد). خودِ سایت با ۱GB رم کار می‌کند؛ اگر بانک سؤال را چند برابر کردی، به ۲GB فکر کن.

## تنها نکتهٔ ظریف: مرحلهٔ «build»

ساختِ نسخهٔ نهاییِ کلاینت (`npm run build`) لحظه‌ای تا ~۴۵۰MB رم می‌گیرد. روی پلنِ ۱GB معمولاً موفق می‌شود، اما اگر هاست بخشی از رم را برای خودش نگه دارد ممکن است تنگ شود. سه راهِ حل (خیالت راحت):

1. **بهترین راه — build را روی کامپیوترِ خودت بزن، فقط خروجی را آپلود کن:**
   - روی ویندوزِ خودت: پوشهٔ `client` → `npm install` → `npm run build`
   - بعد فقط پوشهٔ `client/dist` را (که فقط ۳.۳MB است) روی هاست بگذار.
   - این‌طوری هاست **اصلاً نیازی به build ندارد** و ۱GB رم برایش فراوان است. (این تمیزترین روش است.)
2. یا موقعِ build روی هاست، به Node حافظهٔ کمتری بده:
   `NODE_OPTIONS=--max-old-space-size=768 npm run build`
3. یا اگر خواستی بدونِ دردسر باشد، پلنِ **RAM: 2GB** را بگیر (تفاوتِ قیمتش کم است و حاشیهٔ امن می‌دهد).

## دربارهٔ CPU: 1 و Hard: 2GB
- **CPU 1 هسته:** برای این اپ کافی است. Node تک‌رشته‌ای/غیرهمزمان است و کارِ سنگینِ محاسباتی ندارد (بدونِ AI سنگین سمتِ سرور؛ بیمار مجازی هم در حالتِ mock بدونِ بار است). برای صدها کاربرِ روزانه مشکلی نیست.
- **Hard 2GB:** برای کد (~۱۷۷MB) + دیتابیس + آپلودها کافی است. **تنها چیزی که با زمان بزرگ می‌شود، فایل‌های آپلودیِ تصویر/ویدیوی محتواست.** اگر قصد داری کلی عکس و ویدیوی سنگین در بانکِ سؤال/بیمار آپلود کنی، به‌مرور ممکن است ۲GB کم بیاید — در آن صورت فقط فضای دیسک را ارتقا بده (رم و CPU لازم نیست).

## جمع‌بندیِ تصمیم

| سناریو | توصیه |
|---|---|
| **می‌خواهی کم‌هزینه شروع کنی و build را روی کامپیوترِ خودت می‌زنی** | پلنِ **2/1/1 کافی است** ✅ (بهترین نسبتِ قیمت به کارایی) |
| **می‌خواهی build را هم روی خودِ هاست بزنی و خیالت کاملاً راحت باشد** | **RAM: 2GB** بگیر (بقیه همان بماند) |
| **قصدِ آپلودِ حجمِ زیادی عکس/ویدیو داری** | بعداً فقط **فضای دیسک** را بالا ببر |

**خط پایانی:** برای راه‌اندازیِ سایتِ MED School، پلنِ **فریم‌ورک پلاس 2GB دیسک / 1 CPU / 1GB RAM کافی است.** سرور خیلی سبک است؛ تنها جایی که ممکن است کمی تنگ شود مرحلهٔ build است که با «build روی کامپیوترِ خودت» یا کمی رمِ بیشتر کاملاً حل می‌شود.
