# راهنمای آپگرید امن سایت + حفظ کامل دیتابیس

این راهنما تضمین می‌کند هنگام بارگذاری نسخهٔ جدیدِ کد (ارتقا/آپگرید سایت)، **هیچ داده‌ای از بین نرود** — نه فقط کاربران، بلکه **همه‌چیز**: سوالات و فلش‌کارت‌ها در همهٔ بخش‌ها، کیس‌های بیمار مجازی، مقالات وبلاگ (و تاریخچهٔ نسخه‌هایشان)، پیشرفت کاربران، امتیازها، تنظیمات، و فایل‌های آپلودی.

## چرا داده‌ها حفظ می‌شوند؟

کل دادهٔ سایت در **یک فایل دیتابیس** (`medlab.db`) و پوشهٔ فایل‌های آپلودی نگه‌داری می‌شود. این‌ها در پوشه‌ای به نام **DATA_DIR** ذخیره می‌شوند که **بیرون از پوشهٔ کد برنامه** است.

مقدار پیش‌فرض در فایل `.env`:

```
DATA_DIR=../medschool-data
```

یعنی اگر پوشهٔ برنامه شما `medschool` باشد، دادهٔ شما در پوشهٔ **کنارِ** آن یعنی `medschool-data` ذخیره می‌شود (یک سطح بیرون از کد). به همین دلیل:

- ✅ اگر هنگام آپگرید **کل پوشهٔ برنامه را پاک و دوباره آپلود کنید** → داده سالم می‌ماند (چون بیرون آن است).
- ✅ اگر فقط **فایل‌ها را روی هم Extract/Overwrite کنید** → داده سالم می‌ماند.
- ✅ سایت هنگام شروع، اگر ببیند دیتابیس از قبل داده دارد، **دوباره seed نمی‌کند** و پیام می‌دهد: «Existing database detected — data preserved».

## سه لایهٔ محافظت (خودکار)

1. **جای امنِ داده:** `DATA_DIR` بیرون از پوشهٔ کد است (بالا توضیح داده شد).
2. **بکاپ خودکار در هر شروع:** هر بار سرور بالا می‌آید، *قبل از هر تغییری*، یک کپی از دیتابیس در `DATA_DIR/backups/` گرفته می‌شود (۱۰ نسخهٔ آخر نگه داشته می‌شود). پس اگر آپگرید مشکلی داشت، بکاپِ سالم دارید.
3. **قفلِ seed:** اسکریپت seed اگر ببیند دیتابیس **هر نوع داده‌ای** دارد (کاربر، فلش‌کارت، کیس، مقاله، پیشرفت و…)، اجرا نمی‌شود تا اشتباهی داده پاک نشود.

## روش آپگرید (گام‌به‌گام روی cPanel)

قبل از آپگرید، برای اطمینان خاطر:

1. **یک بکاپ دستی هم بگیرید** (اختیاری ولی توصیه‌شده):
   - وارد پنل مدیریت سایت شوید → کلیات → ابزار داده (یا از دکمهٔ «ایجاد نسخهٔ پشتیبان»). یک فایل بکاپ ساخته می‌شود.
   - یا از File Manager، پوشهٔ `medschool-data` را یک‌جا Compress و دانلود کنید.

سپس آپگرید:

2. زیپ نسخهٔ جدید را آماده کنید.
3. در cPanel، **فقط محتوای پوشهٔ برنامه (`medschool`)** را با فایل‌های جدید جایگزین کنید.
   - ⚠️ **پوشهٔ `medschool-data` را دست نزنید و پاک نکنید.**
4. اگر `DATA_DIR` را دستی روی مسیر دیگری تنظیم کرده‌اید، مطمئن شوید همان مقدار در `.env` جدید هم باشد.
5. از بخش **Setup Node.js App** → دکمهٔ **Restart** را بزنید.
6. تمام. سایت بالا می‌آید و در لاگ می‌بینید: «✓ Existing database detected — data preserved».

## نکتهٔ مهم دربارهٔ مسیر مطلق (پیشنهادی برای اطمینان بیشتر)

اگر می‌خواهید ۱۰۰٪ خیال‌تان راحت باشد که مسیر داده هیچ‌وقت اشتباه نمی‌شود، به‌جای مسیر نسبی، یک **مسیر مطلق** در `.env` بگذارید (نام کاربری هاست خود را جایگزین کنید):

```
DATA_DIR=/home/USERNAME/medschool-data
```

این‌طور مسیر داده هرگز به محل کد وابسته نیست.

## بازگردانی از بکاپ (اگر لازم شد)

- فایل‌های بکاپ در `DATA_DIR/backups/` با نام `medlab-<تاریخ>.db` هستند.
- برای بازگردانی: سرور را متوقف کنید، فایل بکاپ موردنظر را کپی کرده و به‌جای `DATA_DIR/medlab.db` بگذارید (نام را دقیقاً `medlab.db` کنید)، سپس سرور را Restart کنید.

## چه چیزهایی حفظ می‌شوند؟ (همه‌چیز)

- 👤 همهٔ کاربران (دانشگاهی، رقابتی، اساتید، ادمین) و رمزها
- ❓ همهٔ سوالات، فلش‌کارت‌ها و نسخه‌هایشان — در تمام بخش‌ها
- 🩺 کیس‌های بیمار مجازی، چک‌لیست‌ها، پرامپت‌ها
- 📝 مقالات وبلاگ + تاریخچهٔ نسخه‌ها + دسته‌بندی‌ها
- 📈 پیشرفت یادگیری، XP، استریک، دستاوردها، لیگ‌ها
- 🏫 کلاس‌ها، آزمون‌ها، نتایج و کارنامه‌ها
- ⚙️ تنظیمات سایت، کلیدهای هوش مصنوعی، پرچم‌قابلیت‌ها
- 🖼️ فایل‌های آپلودی (تصاویر و ویدیوها)

همهٔ این‌ها در `DATA_DIR` هستند و با آپگرید حفظ می‌شوند.
