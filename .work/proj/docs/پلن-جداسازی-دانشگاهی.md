# پلن جامع جداسازی مسیر دانشگاهی و مسیر غیر دانشگاهی

تاریخ غربال: ۱۴۰۵/۰۶/۲۰ (۲۰۲۶-۰۹-۱۱) — روی نسخهٔ ۴۷  
هدف: **learner هرگز به دادهٔ دانشگاه نرسد و student هرگز به مسیر Learn/رقابتی نرسد.** هیچ باگ مرزی باقی نماند.

این سند **اجرا نیست**؛ ترتیب کار است. هر فاز بعد از تأیید، جداگانه پیاده + تست + زیپ می‌شود. تغییر بزرگ بدون تأیید این پلن انجام نمی‌شود.

---

## ۰. دو دنیا (قرارداد غیرقابل نقض)

| | دانشگاهی | غیر دانشگاهی (رقابتی) |
|---|---|---|
| نقش | `student` + استاد همان دانشگاه + ادمین | `learner` |
| ورود | استاد/ادمین می‌سازد (شماره دانشجویی) | ثبت‌نام عمومی → همیشه `learner` |
| محتوا | کیس و فلش با `track=university` و `university_id` | کیس و فلش با `track=learn` (بدون دانشگاه) |
| ظرف | کلاس، آزمون زمان‌دار، کارنامه، پژوهش کلاس/آزمون | مسیر Learn، XP، لیگ، mycards، چالش |
| بیمار مجازی | فقط کیس اختصاص‌داده‌شده به کلاس/آزمون/تکلیف | فقط کیس‌های `track=learn` + سوییچ ادمین Learn |
| گزارش | کارنامهٔ دانشجو برای استاد همان دانشگاه | پروفایل/XP خود learner |

**اشتراک مجاز:** موتور چت/نمرهٔ VP (`Exam.jsx` + `exam.js`) به‌شرط اینکه **لایهٔ دسترسی** جدا باشد. پشتیبانی per-user، بلاگ عمومی، فروشگاه عمومی.

**اشتراک غیرمجاز:** بانک کیس، بانک فلش، کلاس، آزمون، کارنامه، روبریک، چک‌لیست، کاتالوگ سفارش دانشگاه، پرسشنامهٔ کلاس/آزمون، رویداد پژوهشی دانشگاه.

دست‌نخورده در همهٔ فازها مگر بگویید: فرمول نمرهٔ نقاشی، `serializeCard` مسیر Learn، `reveal` دانشجو روی check، `canAccessCase` برای آزمون تمام‌شدهٔ **دانشجو**، Admin.jsx با StrReplace، `npm audit fix`، ۵ شکست قدیمی `api.test.js`.

## ۱. آنچه الان درست است (zip-۴۴ تا ۴۷)

- UI: `App.jsx` — learner فقط `LearnApp`؛ student فقط خانه/کلاس/آزمون/فلش؛ staff فقط Admin.
- ثبت‌نام عمومی فقط `learner` می‌سازد.
- همهٔ مسیرهای `/api/learn/*` با `requireRole("learner")` (۱۲۷ مسیر، صفر بدون گیت).
- فلش دانشگاه: GET برای learner تهی؛ check با `university_only`. فلش Learn: دانشجو `wrong_track`.
- `containersFor`: فقط student می‌تواند `class_id`/`exam_id` در attempts بنویسد؛ کلاس و آزمون انحصاری.
- zip-۴۷: learner به `GET /classes`، `GET /classes/:id`، `GET /exams`، leaderboard نمی‌رسد.
- کارنامهٔ استاد `teacherOwnsStudent` نقش غیر student را کنار می‌گذارد.
- دانشجو GET کیس را `studentSafeCase` می‌کند (کلید تشخیص در JSON نیست).

## ۲. باگ‌های زندهٔ تفکیک (غربال همین دور)

این‌ها را در فازهای پایین به ترتیب می‌بندیم. **هنوز کد نزده‌ایم.**

### A. بانک کیس مشترک — نشت اصلی
1. کیس‌ها برخلاف فلش‌کارت **`track` ندارند**. همهٔ کیس‌های فعال دانشگاه در بانک واحدند.
2. `playableCases` / `caseOfTheDay` = همهٔ کیس‌های `active=1` به‌جز آن‌هایی که در آزمون **باز** هستند → شرح‌حال و عنوان OSCE دانشگاه برای learner.
3. `canAccessCase(learner) = !caseInLiveExam` → GET `/cases/:id` شرح کیس دانشگاه را به learner می‌دهد (با `studentSafeCase`).
4. `hasAccess` برای learner بعد از سوییچ VP، chat/order/evaluate همان کیس دانشگاه را اجرا می‌کند (attempts بدون class/exam، ولی **محتوا** دانشگاه است).
5. پنل ادمین `GET /admin/vpatient/cases` همهٔ کیس‌های دانشگاه را برای سقف XP لیست می‌کند.

### B. پرسشنامه / tutor / پژوهش
6. `GET /questionnaires/prompts`: چک عضویت فقط اگر `role===student`. learner با `contextType=class|exam` و یک id فرم کلاس/آزمون را می‌گیرد.
7. `POST /tutor/message` و history برای هر نقش auth است؛ با `contextId` کلاس/آزمون می‌توان tutor دانشگاه را صدا زد.
8. `POST /research/event` بدون `study_id` برای هر نقش ردیف می‌نویسد (جدول پژوهش را آلوده می‌کند).

### C. تنظیمات و کاتالوگ مشترک
9. `GET /settings/:key` برای هر نقش (جز `ai` و `vp_grading`) → learner تنظیمات آزمون دانشگاه (`exam`) را می‌خواند.
10. `GET /order-catalog` بدون نقش → کاتالوگ آزمایش/تصویر دانشگاه برای learner.

### D. لبهٔ نقش staff
11. `canAccessCase` برای هر نقش غیر student/teacher/learner/admin (`content_manager`) همهٔ کیس‌ها را باز می‌کند — QA است؛ باید صریح staff-only شود نه «هر کس دیگر».
12. `GET /cases` و `GET /flashcards` فیلتر دانشگاه فقط برای teacher/student است؛ content_manager همهٔ دانشگاه‌ها را با کلید می‌بیند.

### E. محصول (نه نشت کارنامه، ولی مرز نقش)
13. پرداخت پریمیوم (`/api/pay/subscribe`) برای هر auth — دانشجو می‌تواند اشتراک Learn بخرد.
14. `QuestionnairePrompt` و `DrTutorChat` روی شل learner با `contextType=general` فرم‌های `scope=general` دانشگاه را نشان می‌دهند.

### F. دانشگاهی خالص (غیر از learner) — صف جدا بعد از تفکیک
- پنل روبریک در `Classes.jsx` به API وصل نیست.
- PUT چک‌لیست مشترک بین استادهای همان دانشگاه.
- `session-start` هنوز `gradingRubric` کامل را به دانشجو می‌دهد (عمداً در zipهای قبل نگه داشته شد).
- `evaluate` هنوز `meta.rubric` را در JSON می‌گذارد (عمداً نگه داشته شد).

## ۳. فازها — به ترتیب وابستگی

هر فاز: شکار → تأیید شما اگر تصمیم محصولی دارد → پیاده → تست ماتریسی → زیپ → حذف زیپ قبلی.

### فاز ۱ — قرارداد محتوا: `track` روی کیس (زیربنا)

**تصمیم محصول (باید قبل از کد تأیید شود):**

پیشنهاد پیش‌فرض (مثل فلش‌کارت):
- `data_json.track = "university"` | `"learn"`
- کیس بدون track = university (سازگاری عقب‌رو)
- learner فقط `track=learn`
- student/استاد فقط `track=university` همان `university_id`
- بانک Learn جدا در پنل ادمین Learn (نه تب کیس دانشگاه)

اگر این را رد کنید، گزینهٔ B: ستون/فلگ `learn_visible` روی کیس دانشگاه — **رد می‌شود** چون دوباره محتوا را یکی می‌کند.

**کار:**
- `playableCases` / `caseOfTheDay` / پنل `admin/vpatient/cases` فقط `track=learn`
- سید: چند کیس Learn نمونه تا VP رقابتی خالی نشود (کیس‌های فعلی دانشگاه دست نخورده می‌مانند)
- استاد هنگام ساخت کیس track ننویسد (همیشه university)

**تست:** learner لیست VP شامل کیس دانشگاه نباشد؛ دانشجو کیس Learn را GET نکند.

**فایل‌ها:** `vpatient.js`, `content.js` (parse/create case), `admin.js` vpatient/cases, `seed.js`

---

### فاز ۲ — قفل موتور VP روی مرز نقش

بعد از فاز ۱، بدون track درست این فاز ناقص است.

- `canAccessCase(learner)`: فقط `track=learn` و `!caseInLiveExam` (و ترجیحاً `university_id` تهی)
- `canAccessCase(student)`: هرگز `track=learn`
- `hasAccess` learner: همان + `vpatientAccess` (الان فقط GET کیس vpatientAccess دارد؛ chat/order هم باید)
- `GET /cases/:id` learner: اگر university → ۴۰۳ `university_only` stage access
- `GET /cases` learner: همان [] بماند
- student: همان assigned/class/exam؛ کیس Learn در لیست نیاید
- evaluate/chat/order/session-start: از hasAccess جدید

**تست ماتریس (حداقل):**
| فراخوانی | learner + کیس دانشگاه | student + کیس Learn | learner + کیس Learn + VP خاموش |
|---|---|---|---|
| GET /cases/:id | 403 | 403 | 403 reason=off |
| session-start / chat / order / evaluate | 403 | 403 | 403 |

**فایل‌ها:** `content.js`, `exam.js`, `vpatient.js`  
**نه:** تغییر `studentSafeCase` فیلدها؛ نه `canAccessCase` پنجرهٔ آزمون تمام‌شده برای دانشجو.

### فاز ۳ — بازبینی فلش‌کارت (معمولاً کوتاه)

الان تقریباً بسته است. غربال کامل:
- GET/check/export/import
- آزمون فلش دانشجو vs mycards learner
- `studentMaySeeFlashcard` رزرو آزمون (عمداً برای نشت stem آزمون؛ **بازنویسی حلقهٔ GET فقط با تأیید**)
- کلاس فلش: learner نتواند finish بزند (الان `requireRole("student")`)

خروجی: تست‌های منفی learner روی `/flashcards` و student روی `/learn/mycards`.

---

### فاز ۴ — ظرف دانشگاه (کلاس / آزمون / گزارش)

بیشتر zip-۴۶/۴۷. غربال باقی:
- همهٔ زیرمسیرهای `classes.js` و `exams.js` برای learner/content_manager
- `GET /reports/my` برای learner فقط attempts خودش بدون class/exam (باید تهی از کارنامهٔ دانشگاه باشد)
- `GET /reports/progress/:id` — zip-۴۷ رادار دانشجو خالی است؛ learner هم نباید برچسب چک‌لیست دانشگاه بگیرد
- drawing-inbox, live-board, analytics, gradebook.csv, conversation-log
- استاد دانشگاه A به دانشگاه B نرسد (بیشتر zip-۳۸ تا ۴۱)

ماتریس: learner × هر GET/POST کلاس و آزمون = ۴۰۳.

---

### فاز ۵ — پرسشنامه، tutor، پژوهش، رضایت

- prompts: اگر نقش student نیست، `contextType` کلاس/آزمون را رد کن؛ learner فقط `scope` صریح Learn (یا هیچ فرم دانشگاهی `general`)
- POST response: عضویت اجباری برای class/exam؛ learner نتواند form_id دانشگاه را بفرستد
- tutor: requireRole student برای context کلاس/آزمون؛ learner فقط general/learn
- research POST /event: بدون study معتبر ننویس؛ learner عضو study دانشگاه نشود
- consent: learner به `/consent` مطالعهٔ دانشگاه نرسد

---

### فاز ۶ — تنظیمات، کاتالوگ، چک‌لیست

- `GET /settings/:key`: allowlist per role  
  - student: فقط `exam` (مدت/فلگ‌های سراسری لازم برای UI)  
  - learner: فقط کلیدهای Learn در صورت نیاز؛ **نه** `exam` دانشگاه، نه `vpatient` داخلی اگر کلید دارد  
  - teacher: exam + vp_grading همان دانشگاه  
  - admin: بقیه
- `GET /order-catalog`: student + teacher + admin (+ learner فقط اگر فاز ۲ کیس Learn سفارش دارد — آن‌گاه کاتالوگ Learn جدا یا کاتالوگ عمومی بدون کلید تشخیص)
- چک‌لیست: student/learner هرگز GET کامل؛ content_manager را صریح staff کنید
- PUT settings همان گیت فعلی teacher/admin — نگه دارید

---

### فاز ۷ — کلاینت و هویت

- `App.jsx`: learner هرگز Classes/StudentExams/CaseList؛ student هرگز LearnApp (الان درست — تست رگرسیون)
- `Exam.jsx` embedded برای learner: اگر API ۴۰۳ دانشگاه بدهد، پیام مرحله `access` (الان refusal دارد)
- QuestionnairePrompt / DrTutorChat روی learner: context را general/learn قفل کنید نه class/exam
- پرداخت: subscribe را `requireRole("learner")` کنید مگر بگویید دانشجو هم پریمیوم Learn دارد
- impersonate ادمین: خروج از نقش را قاطی نکند (الان banner دارد)
- دانشجو نتواند نقش را به learner عوض کند و بالعکس (بررسی `PUT /admin/users` و `POST /users/:id/learner`)

### فاز ۸ — ماتریس تست پایدار (شرط «هیچ باگ نماند»)

یک فایل `track-isolation.test.js` (یا بلوک zip در `vp-stability`):

**Learner روی دانشگاه (همه ۴۰۳/تهی):**  
`/classes`, `/classes/:id`, `/exams`, `/exams/:id`, leaderboard, `/cases`, `/cases/:id` (کیس دانشگاه), `/flashcards`, `/flashcards/check` (کارت دانشگاه), `/exam/session-start|patient-reply|order|evaluate` با کیس دانشگاه, `/reports/attempts`, `/classes/:id/gradebook.csv`, prompts با classId, tutor با classId, research consent مطالعهٔ دانشگاه.

**Student روی Learn (همه ۴۰۳):**  
هر `/api/learn/*` نمونه، `/flashcards/check` کارت track=learn، GET کیس track=learn، evaluate کیس Learn.

**استاد:** کیس Learn در بانک دانشگاه نیاید؛ کارنامه learner در attempts کلاس نیاید.

این ماتریس بعد از هر فاز بعدی باید سبز بماند.

### فاز ۹ — صف دانشگاهی خالص (بعد از تفکیک، نه قاطی با Learn)

فقط وقتی مرز نقش قفل شد:
- پنل روبریک استاد (اگر بخواهید؛ تغییر بزرگ UI)
- نشت `gradingRubric` در session-start / `meta.rubric` در evaluate (عمداً تا الان نگه داشته شده)
- PUT چک‌لیست مشترک
- باگ‌های VP دانشجو که isolation نیستند

## ۵. معیار تمام‌شدن

- هیچ endpoint دانشگاهی برای توکن learner دادهٔ دانشگاه برنگرداند.
- هیچ endpoint Learn برای توکن student دادهٔ رقابتی برنگرداند.
- ماتریس فاز ۸ در vitest سبز.
- UI دو شل جدا (الان هست) با API هم‌معنی شود.
- گزارش فارسی هر زیپ: باگ پیدا‌شده → رفع‌شده → هنوز باز.

## ۶. شروع

**قدم بعدی پیشنهادی: فاز ۱+۲ در زیپ ۴۸** — بدون آن بقیهٔ دروازه‌ها سوراخ می‌مانند.

قبل از کد، یک تأیید:
1. کیس Learn جدا با `track=learn` (پیشنهاد) — نه نمایش کیس دانشگاه در رقابتی.
2. تا ادمین کیس Learn نسازد، VP رقابتی ممکن است خالی باشد؛ سید نمونه در همان زیپ گذاشته شود.
3. دانشجو حق پریمیوم Learn نداشته باشد (`pay` فقط learner) مگر خلافش را بگویید.
