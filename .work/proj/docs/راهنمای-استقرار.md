# 🚀 راهنمای استقرار (Deployment) — آنلاین‌کردن MED School

این راهنما قدم‌به‌قدم و به زبان ساده است. با آن می‌توانید سایت را:
- **الف)** روی کامپیوتر یا شبکهٔ محلی خودتان با HTTPS آزمایش کنید، یا
- **ب)** روی یک سرور واقعی با **دامنهٔ خودتان** و HTTPS معتبر آنلاین کنید.

همه‌چیز با **Docker** و **Caddy** انجام می‌شود؛ Caddy گواهی HTTPS را **خودکار و رایگان** می‌گیرد و تمدید می‌کند. نیازی به دانش فنی عمیق ندارید.

---

## 🧰 پیش‌نیاز: نصب Docker

- **ویندوز:** [Docker Desktop](https://www.docker.com/products/docker-desktop/) را نصب و اجرا کنید.
- بعد از نصب، در PowerShell دستور `docker --version` باید نسخه را نشان دهد.

> کل پروژه فقط با «داکر» اجرا می‌شود؛ لازم نیست Node.js را جدا نصب کنید.

---

## ⚡ راه‌اندازی در ۳ گام

### گام ۱ — تنظیمات را بسازید
در پوشهٔ اصلی پروژه، فایل نمونه را کپی کنید و نامش را دقیقاً `.env` بگذارید:

```powershell
Copy-Item .env.deploy.example .env
```

سپس `.env` را با Notepad باز کنید و **حداقل** این یک مقدار را عوض کنید:

```
JWT_SECRET=یک-رشتهٔ-تصادفی-طولانی-اینجا
```

> برای ساخت رشتهٔ تصادفی در PowerShell:
> `[guid]::NewGuid().ToString() + [guid]::NewGuid().ToString()`

> ⚠️ **مهم (امنیت):** در حالت production اگر `JWT_SECRET` را تنظیم نکنید یا مقدار پیش‌فرض را رها کنید، سرور **عمداً بالا نمی‌آید** و پیام خطا می‌دهد. این از یک اشتباه امنیتی جدی جلوگیری می‌کند (اگر رمز پیش‌فرض بماند، هرکسی می‌تواند توکن ورود جعل کند). پس حتماً یک رشتهٔ تصادفی طولانی بگذارید.

بقیهٔ موارد (گوگل، ایمیل، هوش مصنوعی) اختیاری‌اند؛ خالی بمانند هم سایت کار می‌کند.

### گام ۲ — آدرس سایت را مشخص کنید
فایل `deploy/Caddyfile` را باز کنید:

- **برای آزمایش محلی:** کاری نکنید. آدرس پیش‌فرض `https://medschool.localhost` است.
- **برای سایت واقعی با دامنه:** بخش «OPTION A» را از حالت کامنت خارج کنید (# ابتدای خطوط را بردارید)، بخش «OPTION B» را کامنت کنید، و `medschool.example.com` را با دامنهٔ خودتان (مثلاً `medschool.ir`) جایگزین کنید.
  همچنین در فایل `.env` مقدار `APP_URL` را به `https://دامنهٔ-شما` تغییر دهید.

### گام ۳ — اجرا کنید
در پوشهٔ اصلی پروژه:

```powershell
docker compose -f docker-compose.deploy.yml up -d --build
```

چند دقیقه صبر کنید (بار اول ساخت طول می‌کشد). تمام! حالا باز کنید:

- محلی: **https://medschool.localhost**
- واقعی: **https://دامنهٔ-شما**

بار اول به‌طور خودکار دیتابیس با محتوای نمونه پر می‌شود؛ دفعات بعد داده‌های شما دست‌نخورده می‌ماند.

> ⚠️ در حالت محلی، مرورگر ممکن است هشدار «گواهی نامعتبر» بدهد (چون گواهی خودامضاست). روی «Advanced → Proceed» بزنید. در حالت دامنهٔ واقعی این هشدار وجود ندارد.

---

## 🌐 اتصال دامنهٔ واقعی (وقتی سرور خریدید)

1. یک **سرور مجازی (VPS)** با آی‌پی عمومی تهیه کنید و Docker را رویش نصب کنید.
2. در پنل دامنه، یک رکورد **A** بسازید که دامنه را به **آی‌پی سرور** اشاره دهد:
   - `medschool.ir  →  A  →  آی‌پی سرور`
   - (اگر `www` هم می‌خواهید، یک رکورد A دیگر برای `www` بسازید و در Caddyfile هر دو نام را بنویسید.)
3. روی سرور، پورت‌های **80** و **443** باز باشند (فایروال).
4. `deploy/Caddyfile` را طبق گام ۲ (OPTION A) با دامنهٔ خودتان تنظیم کنید.
5. دستور گام ۳ را اجرا کنید. Caddy خودش گواهی معتبر Let's Encrypt را می‌گیرد. ✅

## 💾 پشتیبان‌گیری خودکار

سرویس `backup` به‌طور خودکار **هر ۲۴ ساعت** یک نسخهٔ کامل از دیتابیس را در پوشهٔ `backups/` (کنار پروژه) ذخیره می‌کند و ۱۴ نسخهٔ آخر را نگه می‌دارد.

- تغییر بازه یا تعداد نگهداری: در `docker-compose.deploy.yml` می‌توانید متغیرهای `BACKUP_INTERVAL` (ثانیه) و `BACKUP_KEEP` را به سرویس `backup` اضافه کنید.
- **گرفتن پشتیبان دستی همین حالا:**
  ```powershell
  docker compose -f docker-compose.deploy.yml exec backup sh -c "cp /data/medlab.db /backups/manual_$(date +%s).db"
  ```

### بازگردانی از پشتیبان (Restore)
```powershell
# ۱) توقف
docker compose -f docker-compose.deploy.yml down
# ۲) جایگزینی دیتابیس با یک فایل پشتیبان دلخواه
docker run --rm -v medai-fullstack_medlab-data:/data -v ${PWD}/backups:/b alpine `
  sh -c "cp /b/medlab_2026-07-07_03-00-00.db /data/medlab.db"
# ۳) اجرای دوباره
docker compose -f docker-compose.deploy.yml up -d
```
(نام فایل پشتیبان را از پوشهٔ `backups/` انتخاب کنید.)

## 🔧 دستورهای پرکاربرد

| کار | دستور |
|---|---|
| مشاهدهٔ لاگ‌ها | `docker compose -f docker-compose.deploy.yml logs -f` |
| توقف | `docker compose -f docker-compose.deploy.yml down` |
| اجرای دوباره | `docker compose -f docker-compose.deploy.yml up -d` |
| اعمال تغییرات کد | `docker compose -f docker-compose.deploy.yml up -d --build` |
| وضعیت سرویس‌ها | `docker compose -f docker-compose.deploy.yml ps` |

## 🩺 عیب‌یابی

- **سایت باز نمی‌شود:** چند دقیقه صبر کنید تا ساخت تمام شود؛ `... logs -f` را ببینید. مطمئن شوید Docker Desktop روشن است.
- **هشدار گواهی در حالت محلی:** طبیعی است (خودامضا)؛ Proceed بزنید. در دامنهٔ واقعی وجود ندارد.
- **دامنه به سایت وصل نمی‌شود:** رکورد A و آی‌پی را چک کنید؛ ممکن است انتشار DNS تا چند ساعت طول بکشد. پورت‌های 80/443 باز باشند.
- **سلامت سرویس:** آدرس `https://دامنه/api/health` باید `{"ok":true}` بدهد.

---

## 🔒 نکات امنیتی قبل از انتشار عمومی

1. `JWT_SECRET` را حتماً به یک رشتهٔ تصادفی و طولانی تغییر دهید.
2. رمز کاربران دمو (`admin/teacher/...` با رمز `demo`) را از پنل مدیریت عوض کنید یا حساب‌های دمو را حذف کنید.
3. پشتیبان‌های پوشهٔ `backups/` را جایی امن نگه دارید.
4. اگر ثبت‌نام ایمیلی می‌خواهید، مقادیر `SMTP_*` را در `.env` پر کنید.
