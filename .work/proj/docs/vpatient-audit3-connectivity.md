# بررسی سوم — اجرای واقعی مرورگر و تشخیص مانع اتصال

تاریخ: ۲۰۲۶-۰۹-۱۸. مبنا: audit2، commit `9432089`.

## نتیجه روشن

نصب و اجرای مرورگر این بار موفق شد. ورود دانشجوی آزمایشی، بازکردن کلاس، شروع بیمار مجازی و ارسال سه پیام از UI واقعی اجرا شد. **این اجرا زنده با OpenRouter نبود:** هر سه پاسخ API مقدار `source: mock` داشتند.

تصویر واقعی و بدون بازسازی: `docs/evidence/vpatient-browser-local.png`. تصویر حاصل Playwright/Chromium از رابط خود برنامه است؛ انیمیشن‌های گذرا هنگام ثبت به پایان رسانده شدند. این تصویر به‌تنهایی گواه مدل پاسخ‌دهنده نیست؛ منشأ پاسخ از JSON درخواست واقعی بررسی شد.

## راه‌حل مانع مرورگر

دانلود معمول Playwright در دور قبل ناموفق بود، اما npm در این محیط قابل دسترس است. `playwright-core` و بسته مرورگر `@sparticuz/chromium` از npm نصب شدند. کتابخانه‌های NSPR/NSS همراه همان بسته استخراج و با `LD_LIBRARY_PATH` برای اجرای مرورگر استفاده شدند. تلاش apt موفق نبود؛ کتابخانه‌ای از منبع ناشناس دریافت نشد.

مرورگر محلی با headless Chromium اجرا شد. بررسی TLS غیرفعال نشد. مسیر مرورگر محلی به برنامه روی loopback همان sandbox بود؛ این URL وارد کد کلاینت یا لینک سرویس قابل‌استفاده توسط مرورگر کاربر نشده است. سرور پیش‌نمایش روی `0.0.0.0:4000` گوش می‌دهد و درخواست‌های کلاینت نسبی‌اند.

مرورگر، بسته‌های کمکی و دیتابیس آزمایشی وارد ZIP نمی‌شوند. این راه‌حل محیطی است، نه وابستگی جدید برنامه.

## آزمون شبکه

| مقصد / روش | مشاهده واقعی |
|---|---|
| OpenRouter catalog با curl HTTPS | خطای TLS/SSL؛ HTTP 000 |
| OpenRouter با Chromium | `net::ERR_CONNECTION_CLOSED` |
| OpenRouter با HTTP عمومی بدون کلید | پاسخ خالی؛ درخواست احرازشده بدون TLS ارسال نشد |
| GitHub API با curl | HTTP 200 |
| npm registry با curl | HTTP 200 |
| example.com با curl HTTPS | خطای TLS/SSL؛ HTTP 000 |
| GitHub API با Chromium | خطای اعتماد گواهی؛ اعتبارسنجی خاموش نشد |

پس تعبیر «تمام اینترنت محیط قطع است» دقیق نیست. دسترسی به برخی مقاصد برقرار است؛ علت دقیق بسته‌شدن اتصال OpenRouter از این شواهد به‌تنهایی تعیین نمی‌شود. DNS در دسترس است. این وضعیت با ناتوانی عمومی در اجرای مرورگر یا چت برنامه یکسان نیست.

هیچ متغیر تنظیم‌شده `OPENROUTER_API_KEY` یا proxy در محیط یافت نشد. کلید ثابت حذف‌شده در ممیزی دوم بازگردانده نشد. از پراکسی ثالث، تونل GitHub، خاموش‌کردن TLS یا ارسال کلید به واسطه برای دورزدن مانع استفاده نشد.

## مسیر دانشجویی که واقعاً اجرا شد

1. بازکردن landing در Chromium؛
2. ورود با حساب دانشجوی seed (داده مصنوعی)؛
3. ورود به «کلاس‌های درسی» و کلاس طب داخلی؛
4. شروع کیس درد قفسه سینه؛
5. سه درخواست از دکمه ارسال رابط، با HTTP 200 و منشأ `mock`:

| پیام | پاسخ |
|---|---|
| سلام، اجازه می‌دهید چند سؤال بپرسم؟ | سلام دکتر، می‌توانید سؤال بپرسید. |
| از کی شروع شده؟ | درد از ۲ ساعت پیش هنگام فعالیت شروع شده |
| درد به کجا انتشار دارد؟ | فشارنده و با انتشار به بازوی چپ و فک |

این یک smoke test دسکتاپ با viewport برابر ۱۴۴۰×۱۰۵۰ است؛ پایان و ارزیابی، موبایل، همه مراحل و تمام کیس‌ها در این اجرای مرورگر آزموده نشدند. اجرای قبلی API شامل بررسی گسترده‌تر بود، ولی آزمون API جای مرورگر را نمی‌گیرد.

اجرای نخست به دلیل انتظار `networkidle` timeout شد؛ در اجرای موفق، آماده‌شدن DOM و عناصر مشخص و پاسخ API انتظار داده شد. از timeout نخست، خرابی برنامه نتیجه‌گیری نمی‌شود. حساب استاد و دانشجو برای بررسی مسیرهای UI آزمایش شدند؛ تصویر نهایی مربوط به دانشجو است.

## آنچه برای آزمون زنده باقی است

1. دسترسی HTTPS محیط اجرا به `openrouter.ai:443` باید برقرار شود؛ بررسی مجوز/تنظیم شبکه محیط در اختیار میزبان Arena یا پشتیبانی آن است، نه کد این مخزن. مشخصات خطای بالا برای پیگیری قابل‌استفاده‌اند.
2. کلید جایگزین باید از تنظیم امن محیط یا پنل مدیریت برنامه وارد شود؛ نه چت و نه فایل انتشار.
3. سپس ابتدا کاتالوگ و یک completion واقعی، با ثبت منشأ و مدل پاسخ‌دهنده بررسی شوند؛ بعد بنچمارک چندمدلی و گفت‌وگوی UI انجام شود. صرف اسکرین‌شات یا HTTP 200 مسیر برنامه، موفقیت مدل زنده را ثابت نمی‌کند.

هیچ completion زنده OpenRouter در این دور دریافت نشد. به جزئیات جلسه قدیمی اشاره‌شده توسط کاربر دسترسی نداشتیم؛ موفقیت یا مدل استفاده‌شده در آن جلسه مستقلاً تأیید یا رد نشده است.

## انتشار

کد، تنظیمات انتشار، بانک‌ها، کلاینت ساخته‌شده و تست‌ها نسبت به audit2 تغییر نکردند. فقط این گزارش و تصویر به بسته افزوده شدند. اعداد ۱۱۷۲ تست موفق بک‌اند، یک شکست lint بانک و ۲۱ تست موفق کلاینت مربوط به اجرای audit2 هستند و در این دور دوباره اجرا نشدند. ریسک‌های بالینی و اختلاف نمره فارسی/انگلیسی گزارش قبلی همچنان بازند.
